# Плейбук: Memory-форензика Windows (Volatility 3)

**Тип:** процедура реагирования / форензического анализа
**Платформа:** Windows Server 2022 (DC), стенд KSC-SRV (zunami.lab), Wazuh 4.9.2
**Инструмент снятия:** WinPmem · **Анализ:** Volatility 3 (Framework 2.28.2)
**Автор:** Богданов А.В. · **Статус:** отработано на учебном стенде

---

## 1. Назначение

Плейбук описывает полный цикл анализа оперативной памяти Windows-хоста
при подозрении на компрометацию: снятие дампа, анализ четырьмя базовыми
плагинами Volatility 3, критерии отличия легитимного от вредоносного и
связку находок с алертом в SIEM (Wazuh).

Ключевой принцип: **каждая техника атаки видна тем плагином, который ей
соответствует.** Отсутствие находки в одном плагине не означает «чисто» —
его нужно либо объяснить («вектора не было»), либо отклонить как ложное
срабатывание. «Чистый дамп» — это не «malfind ничего не нашёл», а
«каждый кандидат объяснён и отклонён».

---

## 2. Когда применять

- Сработал алерт на хосте (например, подозрительный процесс/PowerShell),
  нужно подтвердить или опровергнуть компрометацию по памяти.
- Подозрение на бесфайловую атаку, инжект кода, скрытый процесс.
- Триаж L1→L2: память как источник, подтверждающий или опровергающий
  событие SIEM.

---

## 3. Снятие дампа (WinPmem)

На целевом хосте, от администратора:

```powershell
C:\Tools\winpmem.exe memdump.raw
```

- Снимать **как можно раньше** после обнаружения — память летучая.
- Если в памяти должен «жить» короткоживущий процесс — убедиться, что он
  ещё запущен на момент снятия (проверить `Get-Process`).
- **Артефакт наблюдателя:** сам `winpmem.exe` попадёт в дамп. Это ожидаемо
  и не является угрозой — аналитик обязан отделять свой инструментарий от
  действий атакующего.

### Передача дампа на станцию анализа

На хосте (в папке с дампом):
```powershell
python -m http.server 8000
New-NetFirewallRule -DisplayName "temp8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
```
На станции анализа (Ubuntu):
```bash
wget http://<IP-хоста>:8000/memdump.raw
```

## 4. Подготовка Volatility 3

```bash
git clone https://github.com/volatilityfoundation/volatility3.git
cd volatility3
python3 vol.py -f ~/memdump.raw windows.info
```

`windows.info` проверяет, что дамп читается и символы (PDB) скачиваются.
Фиксируем: версию/билд ОС, `SystemTime` (время снятия), разрядность.

> **Важно про версию:** в Volatility 3 2.28.2 плагин `windows.netscan`
> **отсутствует** (сетевые структуры Windows временно не парсятся).
> Всегда сверяйся со списком `choose from`, который тулза выдаёт при
> ошибке — набор плагинов меняется между версиями.

## 5. Четыре базовых плагина: что ищем и критерии

### 5.1 `windows.pslist` — список процессов из ядра

```bash
python3 vol.py -f ~/memdump.raw windows.pslist
```

Проверяем **иерархию родства** (PID→PPID), не имена:

| Эталон | Признак нормы |
|---|---|
| `wininit.exe` → `services.exe`, `lsass.exe` | корректные родители |
| `services.exe` (один) → все `svchost.exe` | svchost всегда от services |
| `lsass.exe` — **единственный** | фейковый lsass = дампер учёток |
| `winlogon` → `userinit` → `explorer` | нормальная цепочка входа |

**Красный флаг:** svchost с родителем ≠ services; второй lsass; системное
имя с «неправильным» родителем.

### 5.2 `windows.psscan` — процессы сканированием памяти

```bash
python3 vol.py -f ~/memdump.raw windows.psscan
```

Находит процессы, **отвязанные** от списка ядра (скрытые) и уже
завершённые. Сравниваем с pslist.

Критерий **настоящего скрытого процесса**:

$$\text{скрыт} = (\text{есть в psscan}) \wedge (\text{нет в pslist}) \wedge (\text{Threads} > 0) \wedge (\text{ExitTime пуст})$$

**Не угроза:** лишние процессы с `Threads = 0` и заполненным `ExitTime` —
это завершённые легитимные процессы (их «призраки» в памяти). Дублирующиеся
offset'ы одного процесса — артефакт сканирования, не malware.

### 5.3 `windows.cmdline` — аргументы запуска процессов

```bash
python3 vol.py -f ~/memdump.raw windows.cmdline
```

Самый читаемый плагин. Проверяем:
- **путь к бинарю:** системные (`lsass`, `services`, `smss`, `csrss`,
  `winlogon`) — только из `C:\Windows\System32`;
- **`svchost.exe` обязан иметь ключ `-k <группа>`.** Голый svchost без
  `-k` = malware;
- **аргументы:** `-enc`, `-nop`, `-w hidden`, `IEX`, `DownloadString`,
  `FromBase64String`, пути из `\Temp\`, `\AppData\`.

Процессы вне System32 допустимы по контексту: Defender из
`ProgramData\Microsoft\Windows Defender\Platform`, Kaspersky из
`Program Files (x86)`, агенты мониторинга.

### 5.4 `windows.malfind` — инжект кода (T1055)

```bash
python3 vol.py -f ~/memdump.raw windows.malfind
```

Ищет регионы `PAGE_EXECUTE_READWRITE` (RWX) + приватная память + тег
`VadS`. **malfind не бывает пустым** — решает содержимое hexdump, не сам
факт попадания в список.

| Содержимое RWX-региона | Трактовка |
|---|---|
| нули и указатели (`...fd 7f 00 00`) | CLR/.NET-рантайм → **ложное** |
| реальный x64-код в `MsMpEng.exe` | движок Defender → **ложное** |
| код в системном процессе (`lsass`, `explorer`, `svchost`) | **угроза** |
| hexdump начинается с `FC 48 83 E4 F0` | стейджер Metasploit/CobaltStrike → **угроза** |

Известные ложные источники RWX: `MsMpEng`, .NET-процессы
(`Microsoft.ActiveDirectory.WebServices`, `sqlceip`, `ServerManager`),
`powershell.exe` (построен на CLR), `SearchApp`, `smartscreen`.

### 5.5 (доп.) `windows.svcscan` — службы из памяти (T1543.003)

```bash
python3 vol.py -f ~/memdump.raw windows.svcscan | \
  grep -iE "temp|appdata|\.ps1|-enc|powershell|cmd.exe|\.bat"
```

Закрепление через службу. **Красный флаг:** `Binary` службы указывает в
`\Temp\`, `\AppData\`, на `cmd/powershell -enc`, LOLBin, или случайное
имя службы. grep — только сито: каждого кандидата смотреть глазами
(служба `vmicvmsession` содержит слово «PowerShell» в имени, но это штатный
Hyper-V — ложное срабатывание фильтра).

Бьётся с правилом корреляции **100700** (закрепление через службу).

## 6. Карта «техника → плагин»

| Техника атаки | MITRE | Каким плагином видно |
|---|---|---|
| Иерархия/подмена процесса | T1036 / T1055 | `pslist` |
| Скрытый (отвязанный) процесс | T1055 / rootkit | `psscan` vs `pslist` |
| Обфускация команды | T1027 | `cmdline` |
| Вредоносный интерпретатор | T1059.001 | `cmdline` |
| Инжект кода в память | T1055 | `malfind` |
| Закрепление через службу | T1543.003 | `svcscan` |

**Главный вывод:** атака видна ровно тем плагином, которому соответствует
её техника, и невидима остальным. Это не слепое пятно инструмента, а
карта соответствий, которую аналитик держит в голове.

## 7. Разбор: чистый дамп

Анализ четырьмя плагинами подозрений не выявил:
- **pslist** — иерархия канонична (svchost от services с `-k`, lsass
  единственный, пути System32);
- **psscan** — скрытых процессов нет (расхождения с pslist = завершённые
  процессы с `Threads=0` и заполненным `ExitTime`);
- **cmdline** — вредоносных аргументов нет, подмены системных бинарей нет;
- **malfind** — только штатные RWX движка Defender (MsMpEng) и .NET/CLR.

**Вердикт: хост чист по памяти** (каждый кандидат объяснён и отклонён).

## 8. Разбор: грязный дамп (учебная атака)

**Нагрузка:** PowerShell с обфусцированной командой
`-nop -w hidden -enc <base64>` (T1027 + T1059.001). Это **НЕ инжект кода** —
это закодированный запуск. Декодирование полезной нагрузки:

```bash
echo '<base64>' | base64 -d | iconv -f UTF-16LE -t UTF-8
```
(`-enc` принимает Base64 из UTF-16LE — отсюда нули между буквами в hex.)

Результаты по плагинам:

| Плагин | Результат | Трактовка |
|---|---|---|
| `cmdline` | **единственный** показал PID 8168 с `-nop -w hidden -enc` | поймал обфускацию ✅ |
| `pslist` / `psscan` | показали 8168 как обычный `powershell.exe`, **без аргументов** | неотличим от легитимного — плагины не выводят аргументы |
| `malfind` | 8168 только с CLR-регионами (нули/указатели) | инжекта не было → `-enc` ≠ T1055 |
| `svcscan` | нашего процесса нет | службу не создавали — вектора закрепления не было |

**Урок про pslist/psscan:** они процесс 8168 **видели**, но по ним его
**нельзя отличить** от чистого powershell, т.к. вредоносность спрятана в
аргументах. Это не «не увидели», а «увидели, но не смогли отличить».

## 9. Связка с Wazuh (форензика после алерта)

Алерт правила **100210** (level 13, T1059.001, Execution) на KSC-SRV
(agent 002, 10.0.2.15), источник Sysmon Event 1.

Полный цикл подтверждения:

$$\text{алерт SIEM} \rightarrow \text{дамп памяти} \rightarrow \text{подтверждение в cmdline} \rightarrow \text{триаж}$$

Тот же `ProcessGuid` и та же командная строка PID 8168 совпали в дампе
памяти (Volatility) и в SIEM (Wazuh) — **память подтверждает алерт**.

### Чтение Sysmon Event 1 — два действующих лица

В каждом Event 1 **два** субъекта, и аналитик читает оба:

| Вопрос | Поля | Значение в кейсе |
|---|---|---|
| **что за процесс** | `processId`, `image`, `commandLine` | 8168, powershell, `-nop -w hidden -enc` |
| **кто породил (откуда)** | `parentProcessId`, `parentImage` | 2304, powershell → **запуск программный, не ручной** |
| **от кого (права)** | `user`, `integrityLevel` | `ZUNAMI\Администратор`, High |

**Откуда** и **от кого** — два отдельных факта.
Цепочка `powershell → powershell -enc` — сильный флаг: нормальный админ
набирает команду в своей консоли, а не порождает вторую со скрытым окном
и Base64. Родитель в Event 1 — половина улики.

## 10. Эталон триажа

> **KSC-SRV (agent 002, 10.0.2.15), источник Sysmon Event 1, UtcTime
> 2026-10-11 18:53:46.** Правило 100210 (level 13), MITRE **T1059.001**,
> тактика Execution. Запуск `powershell.exe` из System32 (путь легитимен)
> с командной строкой `-nop -w hidden -enc <base64>` — связка «без профиля
> + скрытое окно + Base64» является почерком атакующего (обфускация T1027
> + сокрытие). Процесс порождён **другой консолью PowerShell**
> (`ParentProcessId 2304`, `ParentImage powershell.exe`) — запуск
> программный, не ручной. Контекст выполнения: `ZUNAMI\Администратор`,
> IntegrityLevel **High**. Декодирование нагрузки
> (`base64 -d | iconv -f UTF-16LE`) →
> `Write-Output "SOC-LAB-MARKER-2026"; Start-Sleep -Seconds 600` —
> содержимое безобидно, но **паттерн запуска подтверждает срабатывание**.
> **Вердикт: True Positive по технике** (вредоносен способ запуска, не
> нагрузка). **Действия L1:** декодировать `-enc` (выполнено),
> зафиксировать цепочку родитель→потомок, проверить наличие такого же
> `-enc` на других хостах; при распространении на ≥2 хоста — **эскалация
> на L2**. **Критичность:** высокая (level 13), но единичный хост,
> нагрузка безвредна → приоритет средний.

**Отличать технику от нагрузки:** True Positive ставится за вредоносный
*паттерн запуска* (`-enc -w hidden -nop`) независимо от содержимого.
После декодирования нагрузка может оказаться безобидной — срабатывание
всё равно подтверждено.

## 11. Чек-лист быстрого прохода

- [ ] Снять дамп WinPmem (как можно раньше)
- [ ] `windows.info` — дамп читается, символы есть
- [ ] `pslist` — иерархия, пути родства
- [ ] `psscan` vs pslist — скрытые процессы (Threads>0 + ExitTime пуст)
- [ ] `cmdline` — пути бинарей, `-k` у svchost, подозрительные аргументы
- [ ] `malfind` — содержимое RWX (код vs нули), отклонить Defender/CLR
- [ ] `svcscan` — службы с бинарём из Temp/AppData/LOLBin
- [ ] Декодировать все найденные `-enc`
- [ ] Сверить находки с алертом в SIEM (ProcessGuid, командная строка)
- [ ] Прочитать `Parent*`-поля Sysmon Event 1
- [ ] Триаж: хост/время/правило/MITRE/родитель/права/вердикт/действия

## 12. Главные уроки

1. **«Чисто» нужно обосновать,** а не констатировать: каждый кандидат
   malfind/psscan объяснён и отклонён.
2. **Техника → плагин:** тишина в плагине = либо вектора не было, либо
   ложное. Это разные «пусто».
3. **`-enc` ≠ инжект:** обфускация (T1027, видит cmdline) и инжект кода
   (T1055, видит malfind) — разные техники.
4. **pslist/psscan не детектируют обфускацию** — они не выводят аргументы;
   вредоносность в аргументах видит только cmdline.
5. **Sysmon Event 1 — два лица:** процесс и его родитель; «откуда» и «от
   кого» — отдельные факты.
6. **Артефакт наблюдателя:** свой инструмент (winpmem) в дампе — не угроза.
7. **Техника vs нагрузка:** вердикт по паттерну запуска, не по содержимому.
