# Плейбук реагирования: Pass-the-Hash (PtH)

**MITRE:** T1550.002 (Use Alternate Authentication Material: Pass the Hash)
**Тактики:** Lateral Movement, Defense Evasion
**Правило детекта:** 100600 (level 13), родитель `if_sid 92652/92657`
**Платформа:** Windows AD, Wazuh 4.9.2
**Автор:** Богданов А.В. · Отработано на стенде KSC-SRV (zunami.lab)

---

## 1. Что это за атака

Pass-the-Hash — аутентификация по **NTLM-хешу** пароля вместо самого пароля. Атакующий, добыв хеш (дамп LSASS, SAM, NTDS), использует его напрямую: NTLM принимает хеш как доказательство владения паролем. **Пароль знать не нужно.**

Инструменты: impacket (`psexec.py`, `wmiexec.py`, `smbexec.py` с `-hashes`), mimikatz `sekurlsa::pth`, CrackMapExec.

---

## 2. Триггер и телеметрия

| Поле | Значение при PtH |
|---|---|
| EventID | **4624** (успешный сетевой вход) |
| `LogonType` | **3** (сетевой) |
| `AuthenticationPackageName` | **NTLM** (не Kerberos!) |
| `LogonProcessName` | **NtLmSsp** |
| `IpAddress` | внешний/необычный хост |
| `TargetUserName` | атакуемая учётка (часто привилегированная) |

Срабатывает правило **100600** (надстройка над 92652 — «Successful Remote Logon»).

---

## 3. Первичный триаж

Проверить по порядку:

1. **Источник** (`IpAddress`) — известная ли это рабочая станция? Внешний/незнакомый IP = флаг.
2. **Учётка** (`TargetUserName`) — привилегированная? `-500` (встроенный админ) или член Domain Admins = критичность выше.
3. **Пакет аутентификации** — **NTLM** на доменную машину, где ожидается Kerberos, = аномалия.
4. **`WorkstationName`** — **пустое** поле выдаёт автоматизированный инструмент (impacket не передаёт имя).
5. **Субъект** — `S-1-0-0` (NULL SID), `logonGuid {0000...}` — признаки входящего сетевого NTLM.
6. **Частота** — серия входов за секунды (`firedtimes`) = почерк инструмента, не человека.

> **Ключевой нюанс:** событие 4624 **НЕ отличает** вход по хешу от входа по паролю — PtH выглядит как обычный NTLM-вход. Вердикт выносится **по совокупности индикаторов**, а не по одному полю.

---

## 4. Критерии вердикта

| Вердикт | Когда |
|---|---|
| **True Positive** | NTLM type 3 + внешний/неизвестный IP + привилегированная учётка + пустой WorkstationName + серия входов |
| **Benign TP** | Легитимный инструмент/скрипт использует NTLM (старое ПО, бэкап, сканер) — подтверждён владельцем, входит в белый список |
| **False Positive** | Легитимный NTLM-вход, объяснимый по контексту (нет чужого IP, известная учётка/хост) |

---

## 5. Сдерживание (Containment)

- **Изолировать** целевой хост от сети (сетевая изоляция / Active Response netsh).
- **Заблокировать** IP-источник атаки на периметре/сегменте.
- **Завершить** активные сессии скомпрометированной учётки на цели (`query session` / `logoff`).
- Проверить, не было ли **успешных входов** с того же IP на другие хосты (боковое перемещение).

---

## 6. Устранение (Eradication)

- **Сбросить пароль** скомпрометированной учётки — это **инвалидирует украденный NTLM-хеш** (хеш = производная пароля; новый пароль → новый хеш → старый бесполезен). Это специфика именно credential-атак.
- Если скомпрометирована привилегированная учётка — сбросить пароли **всех** привилегированных учёток, с которыми она могла взаимодействовать.
- Найти и удалить источник утечки хеша (дамп LSASS, доступ к SAM/NTDS).
- Проверить персистентность на затронутых хостах.

---

## 7. Восстановление (Recovery)

- Вернуть хост в сеть после проверки на компрометацию.
- Мониторинг повторных NTLM-входов с подозрительных IP.
- Проверить целостность учёток и членства в привилегированных группах.

---

## 8. Эскалация на L2/IR

Немедленно, если:
- скомпрометирована **привилегированная** учётка (Domain Admin, `-500`);
- **успешные** входы с источника на **нескольких** хостах (подтверждённое боковое перемещение);
- PtH сопровождается другими техниками (дамп LSASS, персистентность).

**Что передать:** rule.id, timestamp (UtcTime события), agent.name/IP, TargetUserName, IpAddress источника, LogonType, число входов, связанные события (4672, Sysmon 10 если был дамп).

## 9. Эталон триажа

> **KSC-SRV (agent 002, 10.0.2.15), Security 4624, UtcTime 2026-10-15 08:52:46.** Правило 100600 (level 13), T1550.002, Lateral Movement + Defense Evasion. Сетевой вход (LogonType 3) под учёткой **Администратор (S-500)** с внешнего IP **10.0.2.4**, пакет **NTLM (NTLM V2)**, процесс NtLmSsp. Индикаторы PtH: NTLM вместо Kerberos на привилегированную учётку, неизвестная рабочая станция, **пустой WorkstationName**, анонимный субъект (S-1-0-0, нулевой logonGuid), серия из 5 входов за секунды. Событие 4624 не отличает хеш от пароля — вердикт по совокупности. **Вердикт: True Positive (подозрение на PtH, высокая уверенность).** **Действия:** изоляция хоста, блок 10.0.2.4, сброс пароля Администратора (инвалидирует хеш), проверка входов с IP на другие хосты. **→ Эскалация на L2.** Критичность: критическая (привилегированная учётка).

## 10. Извлечённые уроки

- **Правило проверяется в боевом потоке**, а не по догадке о родителе: реальный `if_sid` (92652) отличался от предполагаемого (92657). Проверять живым событием.
- Фильтр **`negate \$$`** по `targetUserName` отсекает машинные учётки.
- Фильтр **`negate loopback`** по `ipAddress` убирает локальный шум (`::1`/`127.0.0.1`).
- Профилактика PtH: ограничение NTLM, LAPS, Protected Users, Credential Guard, запрет сетевого входа привилегированных учёток.
